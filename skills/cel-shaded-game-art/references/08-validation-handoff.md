# 验证与交付

本章主要是综合 M/S/B/R/O 的工程建议，不是原演讲承诺的通用实现规范。来源对应：M pp. 17-21、79-84；S pp. 31-42；B pp. 7-15、58；R pp. 17、37、53；O pp. 37-62、67-79。

## 1. 用最小证据定位问题

- **默认姿态就不像**：先看比例、剪影、关键面部结构和参考镜头，不先堆纹理细节。
- **摆动作才失形**：先排轴心/比例，再看刚性与变形区拓扑、权重；判断是否为 LBS 的可达位置限制，再考虑辅助骨。
- **连续动画才跳**：隔离 IK、Aim/Up、旋转插值、切换偏移与缩放继承；不要只比动画起止两帧。
- **本体轮廓正确但明暗脏**：检查法线来源、光源、阈值和变形；与轮廓描边分开诊断。
- **硬边/发丝断线**：检查挤出方向与光照法线是否误共用，以及导入器是否覆盖第二方向。
- **近远/变焦线宽变**：检查投影、FOV、分辨率和挤出空间，不只调全局宽度。
- **凹槽线浮**：检查本体与壳间隙，局部闭合；**面部内线多**：测试局部深度控制，两者不能混为一谈。
- **只在引擎出问题**：先比导入前后通道、三角化、初始矩阵、动画烘焙和渲染状态，再改源模型。

每次只隔离一个主要变量，保留相同镜头、光源、材质、动作帧的对照。若多个原因叠加，写出已排除与仍待验证项。

## 2. 开工前记录的项目契约

根据实际项目补齐，不将占位值直接写进资产：
- 模型用途、目标镜头、投影类型、屏幕占比与支持的动作/表情。
- DCC/导出器/引擎版本、渲染管线、目标设备与已有 Shader。
- 单位、朝向、根节点、骨骼语义、默认姿势与动画根运动策略。
- 网格/骨骼/材质/实例数预算与性能目标；数字来自项目或测量，不能由本包臆造。
- normals、tangents、UV、vertex color 各通道占用，精度、保留/重算方式。
- 哪些约束烘焙到动画，哪些由运行时系统求值，是否包含缩放和镜头修正。
- 允许的穿插、固定镜头特例、平台差异、资产和工具的修改范围。

## 3. 最小测试矩阵

按角色真正具备的部件裁剪，不给无手无脚的角色硬加人形测试。

### 造型与可读性
- 默认姿势、代表姿态；正面、两侧三分之四、侧面及项目仰俯视。
- 实际游戏显示尺寸与近景，亮/暗/复杂背景。
- 脸颊、下颌、嘴角、眼睛与附属物保持识别性。

### 形变与约束
- 深蹲/跪姿、前抬腿/侧跨、躯干弯扭、肩部抬落、肘深弯、腕扭、抓握、头颈转动，选择实际适用项。
- 关键帧之间的连续过渡、反向播放、超出常用范围但仍属于允许范围的姿态。
- 检查体积、折痕、穿插、接地、局部鼓包、翻转、手脚滑动及控制切换。
- 非等比缩放单列；先测最小父子骨架，再测整角色。

### 阴影与描边
- 固定和变化光向；静态与表情/骨骼旋转后的法线。
- 近/远、宽/窄 FOV、画幅中心/边缘、分辨率变化及实际正交相机。
- 硬边、发梢、衣褶深槽、袖口内壁、面部内线、多个角色相互遮挡。
- 本体单独、描边单独和组合逐项对照。

### 导出与性能
- 导出再导入新场景，比对单位、朝向、骨骼、材质、法线、切线、顶点色、蒙皮与动画。
- 检查目标引擎编译/控制台，确认数据通道未被重算或优化掉。
- 测一个角色与预期同屏实例数，区分 CPU 动画、GPU 蒙皮、顶点、像素、绘制调用与内存开销；不要仅凭三角面数判断。

**合格标准**由项目决定：例如线宽误差、穿插容忍、动画连续性、帧时预算。没有约定时提出待确认标准，不能拿任意阈值假装已验收。

## 4. Unity 适配边界

本技能没有 Unity 工程、编译通过的 Shader 或自动安装器。没有实际打开目标 Unity 项目并执行相应测试时，明确写“Unity 未实测”。

实施前确认 Editor 版本、Built-in/URP/HDRP 或自定义管线及版本、平台、图形 API、已有导入器和 Renderer。某种多 Pass 在一个管线可用，不代表其他管线自动兼容。实施方案以该版本官方文档和最小试验为准，不复制课件历史能力表当支持承诺。

最低运行验证：
1. 新的测试场景导入副本，核对 normals/tangents/vertex color 的实际数据和导入设置。
2. 播放含极限弯曲、扭转、约束烘焙、缩放的最小动画，和 DCC 同帧对照。
3. 测描边渲染状态、相机、深度与同屏遮挡；若切线另作他用，同时检查法线贴图。
4. 查看控制台与帧/性能分析结果，在目标构建或设备上复验关键项。

只能做文件结构检查时，不要使用“Unity-ready”“零报错可用”“已通过性能验收”等表述；说明还缺什么证据。

## 5. 证据分层与交接格式

在报告中分开：
- **资料依据**：文件代号、PDF 页序、转述要点。
- **检查/推演**：查看过什么资产、脚本或静态截图，哪些结论只是逻辑方案。
- **DCC 实测**：软件版本、动作/镜头、观察结果和证据。
- **引擎/设备实测**：版本/管线/构建、操作、结果、日志/截图或测量。
- **未验证**：缺少的环境、数据、动作或权限及最小下一步。

交付规模较小时，用简短条目即可；不要为了模板制造大量空报告。需要完整交接时列出修改文件、数据契约、关键决策、来源、通过与失败项、未验证项和回退方法。

复核报告里的页码时查[来源索引](00-sources.md)。对角色形变或线条效果的结论，附上对应动作帧、镜头和软件版本，方便接手者重做同一个对照。
